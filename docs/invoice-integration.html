حط بيانات الفاتورة في invoice.json

Put invoice data in invoice.json

في مثال الملفات حطّه في examples/invoicing/invoice.json. في نظامك ممكن تبعت نفس الـobject من الـERP أو من endpoint على خادمك. seller للبائع، buyer للعميل، وlines للبنود والضريبة. الأسعار والكميات نصوص عشرية.

Save it as examples/invoicing/invoice.json for this example. In your application, pass the same object from your ERP or a server endpoint. Use seller, buyer, and lines for parties, items and tax. Pass quantities and prices as decimal strings.

02
حط إعدادات زاتكا في خادم Node
Configure ZATCA on your Node server

    
في مثال المستودع، حط الكود في examples/invoicing/example.ts جنب ملف invoice.json. في تطبيقك حط إعدادات الجهاز في ملف التهيئة على الخادم. مرّر شهادة الإصدار اللي استلمتها من Sandbox بعد التهيئة. requestId وbinarySecurityToken وsecret جزء من csid. احتفظ بالقيم الفعلية في مخزن أسرار الخادم.

    
For the repository example, place this code in examples/invoicing/example.ts next to invoice.json. In your application, put per-device settings in your server configuration. Pass the issuance CSID you receive after Sandbox onboarding. requestId, binarySecurityToken, and secret are fields of csid. Load the real values from server-side secret storage.

    
import { createInvoicing } from '../../src/server/invoicing.js';

const csid = {
  environment: 'sandbox',
  kind: 'production',
  requestId: issuedCsid.requestId,
  binarySecurityToken: issuedCsid.binarySecurityToken,
  secret: issuedCsid.secret,
} as const;

const invoicing = createInvoicing({
  environment: 'sandbox',
  csid,
  issuance: {
    egsId: 'device-01',
    xmllintPath: absoluteXmllintPath,
    store,
    signSimplified,
  },
});

    
    
  • kind: 'production' هنا يعني شهادة إصدار. environment: 'sandbox' هو اللي يحدد وجهة الطلب.
  • store مخزن دائم لسلسلة الفواتير ومنع تكرار الإرسال. xmllintPath مسار الأداة لحساب الهاش. signSimplified مزوّد التوقيع الخارجي للمبسطة.
  • لو معاك XML جاهز والهاش، يكفي createInvoicing({ environment: 'sandbox', csid }).

    
  • kind: 'production' identifies an issuance certificate. environment: 'sandbox' selects the destination.
  • store is your durable invoice chain and submission guard. xmllintPath points to the canonicalizer. signSimplified is your external signer for simplified invoices.
  • For ready XML and its hash, use createInvoicing({ environment: 'sandbox', csid }).

  


  

    
03
حوّل JSON إلى XML
Generate XML from the JSON

    
لو عايز ملف XML بس، استدعِ generateXml. الكود يجرّب أول فاتورة لعينة جديدة. في الشغل الفعلي، مرّر الرقم المتسلسل وهاش الفاتورة السابقة من سلسلة الجهاز. الناتج مسودة غير موقّعة.

    
For XML only, call generateXml. This example uses the first invoice in a test chain. In your application, supply the counter and previous invoice hash from the device chain. The result is an unsigned draft.

    
import { readFile, writeFile } from 'node:fs/promises';
import {
  generateXml,
  type InvoiceInput,
} from '../../src/server/invoicing.js';
import { initialPreviousInvoiceHash } from '../../src/xml/index.js';

const invoice = JSON.parse(
  await readFile(new URL('./invoice.json', import.meta.url), 'utf8'),
) as InvoiceInput;

const xml = generateXml(invoice, {
  invoiceCounter: '1',
  previousInvoiceHash: initialPreviousInvoiceHash,
});

await writeFile('invoice-draft.xml', xml, 'utf8');

04
ابعث الفاتورة واقرأ النتيجة
Submit the invoice and read the result

    
لو البداية JSON وعايز نتيجة الإرسال في نفس الاستدعاء، استخدم issueInvoice. الدالة تنشئ XML، وتستدعي مزوّد التوقيع للمبسطة، وتحسب الهاش وتختار الوجهة من kind. استخدم معرّف إصدار ثابت لنفس الطلب.

    
To start from JSON and receive a submission result in one call, use issueInvoice. It creates XML, calls the signer for a simplified invoice, hashes the prepared document and routes by kind. Use a stable issuance ID for the same request.

    
const result = await invoicing.issueInvoice(invoice, invoice.id);
console.log(result.status);

    

      

        
مبسطة B2C · الإبلاغ
Simplified B2C · Reporting

        
مزوّد التوقيع يرجّع XML موقّع وفيه QR المرحلة الثانية. لو معاك الملف جاهز، ابعته مباشرة.

        
Your signer returns signed XML with its Phase 2 QR. If you already have that file, submit it directly.

        
const result = await invoicing.reportXml({
  xml: signedXml,
  invoiceHash,
});

        
reported احفظ النتيجة والـXML الموقّع اللي بعته.Keep the result and the signed XML you sent.

      

      

        
قياسية B2B · التخليص
Standard B2B · Clearance

        
ابعث XML القياسي والهاش. عند القبول، زاتكا ترجع XML بالختم والـQR.

        
Send the standard XML and its hash. On acceptance, ZATCA returns XML with the clearance stamp and QR.

        
const result = await invoicing.clearXml({
  xml: standardXml,
  invoiceHash,
});

        
cleared فك Base64 من clearedInvoiceBase64 واحفظ الملف الراجع.Decode clearedInvoiceBase64 and save the returned XML.

      

    

    
مثال مختصر للنتيجة المتوقعة حسب نوع العينة. تفاصيل التحقق في diagnostics وحالة HTTP في metadata.httpStatus.

    
Abbreviated result for the selected sample type. Validation details are in diagnostics, and the HTTP status is in metadata.httpStatus.

    

    
إذا رجعت already-attempted، اعرض نتيجة المحاولة اللي حفظها تطبيقك. لو انتهت المهلة والنتيجة غير مؤكدة، راجع الطلب قبل إعادة الإرسال.

    
On already-attempted, use the prior result saved by your application. If a timeout leaves the outcome unknown, reconcile it before sending again.

  


  

    
05
لو محتاج QR بس
If you only need a QR

    
generatePhase1Qr(fields) يرجّع حمولة QR المرحلة الأولى. مرّر اسم البائع، الرقم الضريبي، الوقت، الإجمالي والضريبة. في حزمة التطوير نفس الوظيفة اسمها encodeQrBase64 من zatca/qr.

    
generatePhase1Qr(fields) returns a Phase 1 QR payload from the seller, VAT number, timestamp, total and VAT amount. In the development package, use encodeQrBase64 from zatca/qr for the same operation.

    
QR المرحلة الثانية في XML الموقّع للمبسطة أو XML الراجع من تخليص القياسية.

    
For Phase 2, use the QR in the signed simplified XML or in the cleared standard XML returned by ZATCA.
