# مختبر فاتورة ZATCA JS

واجهة محلية لتجربة إنشاء مسودة UBL، وحساب الضريبة والإجمالي، وتوليد QR للمرحلة الأولى، ومقارنة مسار التخليص بمسار الإبلاغ.

## التشغيل

استخدم Node.js 22 أو أحدث. من جذر المشروع شغّل الأمرين التاليين.

```sh
npm ci
npm run demo
```

افتح [مختبر الفاتورة](http://127.0.0.1:4177/). لتجربة نسخة البناء شغّل `npm run demo:build` ثم `npm run demo:preview`. نسخة المعاينة تستخدم نفس خادم XML المحلي.

## تجربة سريعة

1. افتح العينة المبسطة. الكمية 2 وسعر الوحدة 100 ريال. المتوقع صافي 200.00، وضريبة 30.00، وإجمالي 230.00 ريال.
2. افتح «بيانات QR». تظهر الوسوم الخمسة وقيمها وعدد بايتات UTF-8. غيّر اسم البائع إلى «شركة» وأعد الإنشاء. يظهر طول الاسم 8 بايت.
3. افتح «مسودة XML» ونزّل الملف. يحتوي على المبالغ نفسها ومعرّف العينة. زر «تنزيل SVG» يحفظ صورة QR قابلة للمسح.
4. جرّب رقمًا ضريبيًا قصيرًا. تظهر رسالة التحقق وتتوقف إجراءات التنزيل والمحاكاة إلى أن تنشئ مسودة صحيحة.
5. أنشئ مسودة قياسية وشغّل «قبول مع تحذير». تعرض المحاكاة مسار التخليص وحالة `HTTP 202 / CLEARED`. أعد التجربة بمسودة مبسطة لمشاهدة `REPORTED`. جرّب «انتهاء المهلة» لمشاهدة الحالة غير المؤكدة.

## ما ينفّذه المختبر

- يحسب الإجماليات وينشئ مسودة UBL غير موقّعة ويفحص بنيتها بخادم Node المحلي باستخدام وحدات SDK الحالية.
- يولّد حمولة QR للمرحلة الأولى، ويفك الوسوم ويرسم الصورة في المتصفح. يبقى الرمز منفصلًا عن مسودة XML.
- يحاكي ردود التخليص والإبلاغ داخل المتصفح. يُشغّل اختبار التكامل الحي بشكل منفصل بمدخلات Sandbox المخصّصة للاختبار. [دليل Sandbox](m7-zatca-api.md#opt-in-sandbox-runs)

استخدم عينات العرض الاصطناعية. الديمو لا يحتاج OTP أو شهادة أو مفتاحًا خاصًا.

## نتائج الاختبار

نجحت معاينة نسخة البناء في Chrome على الكمبيوتر وعرض بعرض 360 بكسل. نجح تنزيل XML وSVG، وطابقت قراءة صورة QR حمولة Base64 المعروضة، وظهرت حالات القبول والتحذير والرفض وانتهاء المهلة. يغطي `npm test` تطابق الإجماليات بين مسودة XML وQR، وطول الاسم العربي، ورفض المدخلات غير الصالحة.
